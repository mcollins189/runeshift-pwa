## 3. PWA architecture (v1.0 highlight)

### Three-layer cache strategy

1. **Shell cache** `nuz-shell-v2` — pre-cached on `install`, app boots offline. Network-first for HTML, cache-first for everything else. (`sw.js:28`, `sw.js:54`)
2. **PokeAPI runtime cache** `nuz-pokeapi-v1` — stale-while-revalidate for `pokeapi.co/api/v2/*` and `raw.githubusercontent.com/PokeAPI/sprites/*`. Uses `cache: 'no-store'` on the network fetch so we don't double-store (once in Cache Storage, once in the HTTP cache) — halves disk footprint at no user-visible cost since we still return from `hit` immediately. (`sw.js:96`, `sw.js:164`)
3. **Aggressive pre-cache** — opt-in, driven by `prefetch-all` message from page. Concurrency 4, reports per-10-item progress. (`sw.js:233`)

### Service Worker registration

Registered at `sw.js` scope (the directory the SW was served from). Same-origin shell URLs use **relative paths** so the PWA also works at a subpath like `github.io/runeshift-pwa/`. Page-side registration at `tracker.html:9315`; `postToSW()` helper at `tracker.html:9324`; message subscriber at `tracker.html:9336`.

### Message protocol (8 types)

Page → SW:

| Type            | Payload          | Purpose                                       |
| --------------- | ---------------- | --------------------------------------------- |
| `prefetch-all`  | `{ urls: [...] }`| Fill PokeAPI cache with URL list (concurrency 4) |
| `clear-caches`  | —                | Delete every `nuz-*` cache                    |
| `cache-status`  | —                | Count entries in each cache                   |
| `skip-waiting`  | —                | Activate a waiting SW immediately             |

SW → page:

| Type                  | Payload                       | Trigger                                  |
| --------------------- | ----------------------------- | ---------------------------------------- |
| `prefetch-progress`   | `{ done, total }`             | Every 10 URLs during prefetch            |
| `prefetch-done`       | `{ cached, failed }`          | After prefetch completes                 |
| `caches-cleared`      | —                             | After `clear-caches`                     |
| `cache-status-result` | `{ shell, pokeapi }`          | After `cache-status`                     |

The `type` strings are the contract — both sides must match verbatim. See `sw.js:192` for the switch, `tracker.html:9338` for page-side dispatch.

### Pre-cache enumeration (the part with the most landmines)

`buildPrefetchUrlsAllGamesWithRegions(progressFn)` at `tracker.html:9570` builds the all-games URL set:

1. Static per-game species/moves URLs via `_collectPrefetchUrlsForGame`.
2. Sprite IDs 1–1025 (`raw.githubusercontent.com/.../pokemon/<id>.png`). Unused IDs 404 — counted as `failed` and skipped.
3. Evolution chain IDs 1–560.
4. Region URLs for every `GAMES[k].dataSources.pokeapiRegion`.
5. Per-region: locations → areas, with three defenses:
   - **Per-fetch retry-with-backoff**: `_fetchWithRetry` (`tracker.html:9555`) does 5 attempts with delays `[1s, 3s, 10s, 30s]`. 4xx returns immediately (not retried, likely permanent); 5xx + network errors get retried.
   - **Phase-level auto-retry**: `_runPhaseWithRetry` runs each phase up to 3 passes — anything that failed in pass N gets re-run in pass N+1 (`tracker.html:9604`, 9628).
   - **Shape validation**: an empty `data.locations` array throws (treated as "PokeAPI rate-limited with a 200 OK + empty body"), triggering phase retry. Same for malformed location response missing `name`. (`tracker.html:9614`, 9638)

### URL convention — MUST be slug-form with trailing slash

PokeAPI's `region.locations[].url` returns **numeric-ID URLs** (`/location/4/`), but the runtime renderer (`ensureLocationAreasLoaded` + `fetchPokeApiEncounters`) fetches by **slug** (`/location/kanto-route-1/`). If pre-cache stored numeric URLs, runtime fetches would all miss and fall through to "show everything" fallback offline. Pre-cache constructs slug URLs explicitly at `tracker.html:9619`. **Always slug + trailing slash for `/location/`, `/location-area/`, `/pokemon/` URLs** — both at pre-cache time and at runtime fetch sites. There is also a trailing-slash-tolerant lookup in `staleWhileRevalidate` (`sw.js:172`) so a one-side-only mismatch still hits the cache.

### Cache version bumps

| When you change... | Bump... |
| --- | --- |
| Shell file list in `SHELL_URLS` (add/remove file) | `SHELL_CACHE` `nuz-shell-vN+1` (currently v2 after icon-1024 + `log.html`→`tracker.html` rename) |
| PokeAPI response handling (parse changes) | `POKEAPI_CACHE` `nuz-pokeapi-vN+1` (currently v1) |
| Save payload shape (new field) | `version: N+1` in `buildPayload` + add migration branch in `doLogin` |
| Pokemon team object shape (new field) | bump `learnset_vN+1` if related; otherwise default `field || sensibleDefault` in renders |
| Data file structure (txt parser change) | re-run `node build-data.mjs` |
| Icon set | refresh `icons/*.png`, bump SHELL_CACHE if file list changed |

The `activate` handler sweeps any `nuz-*` cache not in the keep-set (`sw.js:77`), so a version bump auto-evicts the old one. Page can also force-clear via `clear-caches` message.

## 4. Save system

### Backends

- **Cloud**: Cloudflare Worker at `https://shrill-darkness-8d1c.mcollins189.workers.dev` (`tracker.html:918`). The save key is the URL path. GET fetches, PUT pushes, 404 = key doesn't exist yet.
- **Local cache**: `localStorage['nuz-save-cache-<key>']` mirrors the cloud snapshot. Used for offline boot, offline edits, and as the "newer copy on cold-login" tiebreaker. (`tracker.html:4481`, 4492)

### Save flow

1. Any mutation calls `save()`, which calls `cloudSave()`.
2. **500 ms debounce** collapses bursts of edits (e.g. editing 5 fields fast = 1 push). (`tracker.html:4925`)
3. If online: `cloudPush` + write local mirror. Status: `saved` (green dot, "Saved HH:MM").
4. If offline: write local mirror only, set `pendingOfflineSave = true`. Status: `offline` (blue dot, "Saved offline HH:MM"). (`tracker.html:5054`, 4744)
5. `online` event auto-flushes pendingOfflineSave (`tracker.html:9326`).

### Offline-created save collision handling

If the user creates a brand-new save while offline, then comes back online, that key may already exist in the cloud. Pre-flight `cloudKeyExists` check on the first push (`tracker.html:4511`, 5086); if collision, prompt user for a new key and loop until free.

### Cross-device resync

- **`visibilitychange = visible`** (`tracker.html:4957`): compare `cloud.lastModified` vs `loadedAt`; if cloud is newer AND no unsaved local changes (`!saveTimer`), silently replace in-memory state + re-render. (`tracker.html:4996`)
- **Cold-login**: if local cache's `lastModified` > cloud's, prefer local + auto-push (`tracker.html:4656`). Catches "made changes offline → switched to a different key → came back" — the local mirror still has the newest data.
- **In-flight guard** `_resyncing` prevents rapid app-switch storms on mobile firing visibilitychange repeatedly (`tracker.html:2217`).

### Status indicators

Header dot, set by `setSaveStatus(type, label)` (`tracker.html:5105`):

| Type      | Color | Meaning                  |
| --------- | ----- | ------------------------ |
| `saved`   | green | Pushed to cloud          |
| `saving`  | amber | In-flight                |
| `offline` | blue  | Saved to local mirror only |
| `error`   | red   | Cloud push failed        |

### Payload + migration

`buildPayload()` (`tracker.html:4526`) returns `{ runs, currentRunId, version: 3, lastModified: Date.now() }`. v3 is backwards-compatible with v2; `doLogin` accepts either (`tracker.html:4674`). `migrateLegacyGameKeys` (`tracker.html:4363`) rewrites retired game keys + remaps `run.version` `S`→`Sw` / `H`→`Sh` for sword_shield runs. `migrateLegacyLocationNames` (`tracker.html:4419`) rewrites typo'd location strings. Both idempotent. Header has `⬇ Export` / `⬆ Import` for JSON dumps.

## 5. Data and display

### Stat calculation

`calcStatAtLevel(baseStats, level, { nature, ability, species })` at `tracker.html:3281`. Gen 3+ formula. Two lookup tables:

- `NATURE_MODS` at `tracker.html:3238` — 25 canonical natures → 6-stat multiplier array. Lowercased lookup (leagues files store `jolly` lowercase).
- `STAT_AFFECTING_ABILITIES` at `tracker.html:3258` — currently bakes Huge Power + Pure Power as Atk × 2. Conditional abilities (Guts, Defeatist, etc.) are surfaced as notes, not baked.

Used at three display sites:
- `renderBossPokeDetail` (`tracker.html:6010`) — boss matchup expansion.
- Speed table at boss matchup (`tracker.html:5859`).
- `pokeView` (`tracker.html:8563`) — roster modal.

**NOT used** in `speciesView` (`tracker.html:8385`) — no level context (it's the "you're considering catching this" preview).

### Encounter rendering dispatch

`renderEncounters()` dispatch order:

1. `dataSources.encounterTables` → `renderEncountersFromTables` (Gen 2, BDSP, SM, USUM, XY, SwSh — rich per-map data).
2. `dataSources.pokeapiRegion` → `renderEncountersByRegion` (offline-capable now thanks to pre-cache fixes).
3. `dataSources.routes` → `renderEncountersFromNuzData` (hack ROMs + SV — txt species lists only).
4. Empty fallback.

XY keeps `pokeapiRegion: 'kalos'` as a fallback for sub-zones the encounter-tables don't cover.

### Encounter-tables file format

Parsed by `parseEncounterTables` in `build-data.mjs:300`:

```
==========
Map: <zoneID> - <Location Name> [(<SubZone>)]
                                ← optional, e.g. "Hau'oli City (Beachfront)"
                                ← Multi-name "Map: NNN - X / MMM - Y" supported
                                ← SwSh uses sub-zone for weather: "Rolling Fields (Overcast)"
Tables: <count>
Table 1 [grass] (Day):          ← (Morning|Day|Night|All) required
Encounters (Levels X-Y): Sp1 (P%), Sp2 (P%), ...
Additional SOS encounters: (None)
```

Method tags: `grass`, `surf`, `oldRod`, `goodRod`, `superRod`, `rockSmash`, `horde`. XY extras: `tallGrass`, `shallowWater`, `yellowFlowers`, `redFlowers`, `purpleFlowers`. Future-proofed for `honey`.

Time-of-day: `Morning` (Gen 2 only), `Day`, `Night`, `All` (XY, SwSh — no time cycle; parser maps `All` → `day` bucket).

Each pool: `{ mapId, tableN, lvMin, lvMax, method, morning:[], day:[], night:[], subZone }`. Cross-version merge key in renderer: `${mapId}#${tableN}#${method}#${subZone||''}`. **lvMin/lvMax are NOT in the key** — was a bug pre-v5.3 (SwSh Serebii scrape sometimes carried slightly different ranges per version for the same conceptual table).

### Boss derivation

`getBosses(gameKey)`:

- **Hand-coded** `GAMES[k].bosses` wins (BDSP, B2W2, USUM).
- If `dataSources.leagues` is also set, `enrichBossesWithLeagues` merges moves/ability/item/nature from the txt file onto hand-coded entries by fuzzy trainer-name match (strips `(Trial)`, "Island Kahuna", "Captain", etc.).
- If no hand-coded `bosses`, `deriveBossesFromData` builds the list from `NUZ_DATA.leagues.<key>` cross-referenced with routes file's `battleType` markers.

`BOSS_BATTLE_TYPES = {gym-leader, elite-four, champion, mini-boss}`. Intentionally excludes:

- `evil-team` — N's BW battles, Ghetsis, Cyrus, Lysandre, Guzma. Story bosses, not cap-defining.
- `event-boss` — HGSS Elder Li / Eusine / Kimono Girls. Sub-boss, not cap-defining.
- `rival` — appears in route trainer lists but doesn't drive caps.
- `titan` — unused since SV Titans were retagged `mini-boss` in v5.3.

`mini-boss` IS included — covers ROM hack cross-region gym leaders (Blaze Black 2, New Generations) and SV (Team Star + Titans).

**Multi-version tier lookup**: paired games walk every version's routes file via `tierByKey`. Catches version-exclusive gym leaders like Iris (W-only). When the same trainer key appears in both versions with different battleTypes, boss-tier outranks rival/evil-team.

**Strict filter**: entries in the leagues file without a matching routes-file `battleType` marker are dropped. Catches leagues-file orphans (XY's AZ, SM's Gladion g2, ORAS Team Aqua admins).

**Rematch dedupe**: within each derived list, when the same trainer name reappears at the SAME location with different caps, only the lowest-cap entry survives. Drops BW/B2W2 second-round Elite Four.

**Name disambiguation** when one trainer has multiple battles: location → theme → cap level → enumeration. E.g. "N — Accumula Town", "Shauntal — Pokémon League (Lv 56)".

Result cached in `_bossesCache[gameKey]`. Cache busted automatically when PokeAPI backfill completes.

### PokeAPI backfill

`backfilledPokemon` + `backfilledMoves` are in-memory caches (`tracker.html:3460`). `fetchPokemonFromApi(species, gen)` at `tracker.html:3601` reads `past_types` so older-gen views see correct typing. **Now also fetches evolution chain** via `fetchEvolutionForSlug` (`tracker.html:3557`) — 2 extra fetches per species, both cached. Backfilled species get `.e = [TargetName, levelOrMethod]` matching the `POKEMON_DB` shape so downstream evo-line dupes / evolution prompts just work.

Insurgence's fakemon evolution syntax `delta-bulbasaur>delta-ivysaur` is parsed and stored on `patches.fakemon` entries (`tracker.html:3954`).

### Learnset

`fetchLearnset(species)` at `tracker.html:4055`. localStorage-cached with 30-day TTL under key **`learnset_v3_<species>`** (bumped from `v2` when `dismissedMoves` shipped; see `getLearnsetLocalKey` at `tracker.html:4043`). Uses slug-form URL (`pokemon/<slug>/`) matching pre-cache. Evolution-learned moves (L0 in modern VGs like `sword-shield`, `bdsp`, `usum`, `sm`) get `isEvo: true` and are pinned to the top of the learnset chart. `renderPokeViewLearnset` (`tracker.html:8766`) splits evo vs level moves; suggestion scorer surfaces them with a lower threshold than level-up moves.

### Evo-move dismissal

`p.dismissedMoves: string[]` tracks moves the user clicked Skip on. Filter applied in `queueLearnableMoves` (`tracker.html:4304`) and the suggestion banner (`tracker.html:8760`) so dismissed moves stop blocking future level-up suggestions. Default-init at `tracker.html:9216`.

### Encounter-tables renderer (`buildEncounterMainFromTables`)

1. **Cross-version structural merge** by key `${mapId}#${tableN}#${method}#${subZone||''}`. On merge, lvMin/lvMax are unioned via min/max.
2. **Post-merge sig-dedup** to collapse identical-content pools (e.g., USUM's bundled Map 000/003/010 producing 3 identical entries).
3. **SwSh weather tabs** — `extractWeather(subZone)` recognizes the 9 weather names (Normal Weather / Overcast / Raining / Thunderstorm / Intense Sun / Snowing / Snowstorm / Sandstorm / Fog). When >1 weather present, a tab strip renders above the encounter sections; weather peeled off `pool.subZone` so any residual (e.g. "Area 2" from "Area 2, Overcast") still labels the sub-section.
4. **Method-based rendering** when pools have method tags: one section per method in canonical order (Walking → Tall grass → Shallow water → Flowers → Surfing → Rods → Rock Smash → Horde). Morning/Day/Night tabs inside the Walking section only.
5. **Methodless rendering** fallback (USUM): groups by level range with a global Day/Night tab.
6. **Sub-zone-aware sub-pool labels** — prefer `pool.subZone` ("1F Outside", "Beachfront", "B2F Mahogany Side") over A/B/C. Siblings sharing the same subZone get A/B/C/D appended.
7. **Per-species version filter** via `matchesVer` — species tagged with the OPPOSITE version filtered out for the user's current selection.
8. **Alola grass sub-method classifier** (SM/USUM): heuristic split of `[grass]` pools into Walking / Rustling grass / Flying overhead / Berry trees in `classifyGrassSubMethod`. Rules: 1 species at ≥95% + whitelisted berry-tree species (Crabrawler / Crabominable / Komala) → Berry; else 1@95% → Rustling. 2–3 species top ≥60% + all-Alola-flying-set (Spearow/Pikipek/Rufflet/Vullaby) → Flying. 2–4 species top ≥50% → Rustling. Otherwise → Walking. Plus a promotion pass that re-labels rustling-only locations to Walking when ≥3 species or sibling levels overlap.

### Sprite priming on cold-login

`_primeBackfillForTeam()` at `tracker.html:5321` iterates the active team, calls `ensurePokemonBackfilled` for each species without `POKEMON_DB` data. Called from `renderRoster` (`tracker.html:5331`) + `renderActive` (`tracker.html:5413`) so cold-login sprites start fetching immediately instead of waiting for the user to navigate to a tab that needs them. The `onBackfill` subscriber at `tracker.html:9817` re-renders every sprite-showing tab (matchup, roster, active, encounters, routes, grave, stats) when data lands.

### Variants (difficulty modes)

Some games ship multiple modes sharing most data but differing on routes/trainers. Modeled as `variants: { letter: 'Label' }` sibling to `versions`. Picked at run-create time, switchable via a header pill, stored on the run as `run.variant`. `dataSources.routes` (and leagues/patches/encounterTables) can be:

- a string: `'Yellow'`
- version-keyed: `{ R: 'Red', B: 'Blue' }`
- variant-keyed: `{ N: 'RadicalRed', H: 'RadicalRedHard' }`
- variant-outer + version-inner: `{ N: { B: 'Black2', W: 'White2' }, C: { B: 'Black2Challenge', W: 'White2Challenge' } }`

`resolveDataSource(srcConfig, game, ver, variant)` walks any of these shapes.

## 8. Deploy workflow

- **Pattern**: stage files in `_to-upload/` (auto-excluded via `_*/`), then drag-drop into GitHub. **Wipe `_to-upload/` at the start of a new batch** so it only contains current changes.

**Deploy file list**:

| Tier | Files |
| --- | --- |
| Required (must ship for any logic change) | `tracker.html`, `data.bundle.js`, `manifest.json`, `sw.js`, `icons/*.png`, `CNAME` |

GitHub web UI converts LF → CRLF on upload, so a freshly-pulled `data.bundle.js` may be 3 bytes larger than a locally-built one (3 line endings × +1 byte for CR). Content is identical after stripping CR — don't chase it as a bug.

**Shipping a new shell file**: add it to `SHELL_URLS` in `sw.js` AND bump `SHELL_CACHE` version (or installed users will run with the old shell until their cache evicts).

## 10. Debugging cheatsheet

Top failure modes and where to start:

1. **"Encounters empty offline"** — PokeAPI path failing. Check pre-cache enumeration completed (Rules tab cache count) AND URLs are slug-form with trailing slash (`tracker.html:9619`). Numeric-ID URLs are silent misses.
2. **"Save status stuck on amber"** — `saveTimer` never cleared. Check `cloudPush` succeeded; if offline, should flip to blue (`tracker.html:5054`).
3. **"Lost edits after switching devices"** — `visibilitychange` resync compared timestamps wrong. Check `cloud.lastModified > loadedAt` AND `!saveTimer` guard at `tracker.html:4996`. Cold-login local-newer case handled at `tracker.html:4656`.
4. **"Offline-created save → online → silently overwrote someone else's run"** — `cloudKeyExists` check at `tracker.html:5086` is the gate. If skipped, audit.
5. **"Sprite missing"** — species not in `POKEMON_DB` AND backfill hasn't fired. Check `backfilledPokemon[slug]` in console; `error` status means PokeAPI 404'd (fakemon).
6. **"Evo move greyed out as already-learned"** — `fetchLearnset` needs `isEvo: true` on the move. L0 detection requires the species to have Gen 7+ VG data. Cache key `learnset_v3_<species>`; clear localStorage to retry.
7. **"Boss missing from cap dropdown"** — trainer's `battleType` is `evil-team` / `rival` / `event-boss` / `titan` (all excluded from `BOSS_BATTLE_TYPES`). Or trainer-key isn't in routes file (strict filter drops). Or rematch hidden by lowest-cap dedupe.
8. **"Version-exclusive badge wrong"** — PokeAPI path: per-pool `letters` set must track ALL versions; only `chance` gated by current `ver`. Encounter-tables path: cross-version merge key is `${mapId}#${tableN}#${method}#${subZone||''}` (NO lvMin/lvMax). SV path: by-file presence in `Scarlet.txt` / `Violet.txt`.
9. **"After deploy, existing save's logged dots gone"** — typo'd location string in saved data doesn't match new rail name. Add the substring rewrite to `LEGACY_LOCATION_NAME_SUBSTRINGS`.
10. **"BDSP mojibake (Ã©, â€™)"** — don't edit txt files via PowerShell `Get-Content` + `Set-Content`. Use Edit tool or Node with explicit `'utf8'`.

**SW debugging tips**:
- Application tab → Service Workers → "Update on reload" + "Bypass for network" when iterating.

## Appendix D: known PokeAPI quirks (and our workarounds)

- **BDSP has zero encounter data**. Bypassed via encounter-tables (TeamLumi).
- **SM/USUM time-of-day stripped** — every `condition_values` array is empty in Gen 7 location-areas. Bypassed via encounter-tables (pk3DS dumps; SciresM gists for USUM, SkyLink98 + pastebins for SM).
- **XY has no condition_values** — zero day/night/horde/Friend Safari data in PokeAPI. Bypassed via encounter-tables (PokemonEncCalc binary).
- **Galar (SwSh) has zero encounter data**. Bypassed via encounter-tables (Serebii scrape).
- **Paldea (SV) has no location-areas at all**. NUZ_DATA-only path with hand-tagged exclusivity in Scarlet.txt / Violet.txt.
- **USUM Alolan forms tagged with `sun`/`moon`**: PokeAPI parks meowth-alola etc. under the older versions. `POKEAPI_GAME_VERSIONS.ultra_sun_moon` lists priority `['ultra-sun', 'sun']` and `['ultra-moon', 'moon']` (not currently exercised since USUM uses encounter-tables).
- **BW/B2W2 seasons mostly missing** — only ~9 of 120 walking-data unova areas carry `season-*` condition values. The renderer hides the season pill where no season-tagged buckets exist.
- **Most of `region/unova` is dead** — 48+ locations have zero encounter data. Rail driven only by txt routes file.
- **Gen 2 super-rod inflated rates** — PokeAPI returns 5 ungrouped slot entries (Qwilfish 10+40+30+20+10 = 110%). Bypassed via pret-sourced encounter-tables.

## Appendix E: name lookup quirks (PokeAPI-driven games)

PokeAPI returns location-area slugs like `kanto-vermilion-city`; `prettifyLocationName` strips the region prefix. Sometimes txt routes names don't strict-match. Solutions:

- **`normLocForApi()`** — strips periods, accents (NFD + combining-marks removal), apostrophe variants, leading "The ", lowercase. Matches `Mt. Moon ↔ Mt Moon`, `Pokémon Tower ↔ Pokemon Tower`, `Hau'oli ↔ Hauoli`.
- **`LOC_NAME_ALIASES`** — small static map: Mirage Forest → Mirage Spot Forest (ORAS), Soaring → Soaring In The Sky, Ruin Maniac's Tunnel → Maniac Tunnel (DP), Nature Preserve → Nature Sanctuary (B2W2), Tin Tower → Bell Tower (HGSS), Rocket Hideout → Team Rocket Hq.
- **Sea-prefix fallback** — retry with `"sea "` prepended. Handles RGBY/FRLG Routes 19/20/21 and GS/HGSS Routes 40/41.
- **Multi-floor merge** (`findRegionLocationsWithFloors`) — when PokeAPI splits one txt location into floor-numbered variants.
- **Multi-region** — `pokeapiRegion` can be an array (`['johto', 'kanto']` for Gen 2 + HGSS).

When fixing typos in `routes/` location names, add the rewrite mapping to `LEGACY_LOCATION_NAME_SUBSTRINGS` in tracker.html so existing saves keep linking.
